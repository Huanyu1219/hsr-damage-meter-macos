# 审查修正第 2 批

本轮修正 Mac 接收端和打包流程，未修改游戏目录或 Collector DLL。

## 变更与原因

- `LiveCombatStore` 将 SQLite 操作交给 `HistoryWorker`。只允许一批在途写入，成功后按事件序号释放缓冲，保留写入期间新到事件及最终结算。失败按 0.5 秒起指数退避；当前战斗最多 8,192 条缓冲，跨战斗队列最多 128 场且合计 262,144 条事件，超过限制明确报告不完整。
- 历史读取和写入等待不会占用统计 Actor；自动清理独立于 10Hz 发布循环。删除只按 SQLite 实际返回的 ID 清理内存，正常退出停止接收后补存未结算事件。
- 数据库拒绝空或异常 BLOB、过大载荷及不支持的版本；检查绑定错误；趋势转换先校验时间和限制范围。现有 schema 1 不变，本次只增加版本保护，不宣称已完成未来模型迁移。
- 下载接收过程中限制小于 25MB，检查声明长度，仅接受指定 HTTPS 来源及重定向；图片限制 1,600 万像素并缩略至 512px，内存缓存最多 128 张，同版本下载复用，旧版本请求不回填新缓存。
- 资料更新的解码、编码和写盘，以及历史导出编码移出主线程；历史列表取消加载时正确释放 loading 状态。
- 临时目录生成完整 App，签名校验成功后通过 macOS 原子目录交换替换成品，构建号递增。退出前增加历史刷新。

主要实现差量见 `2026-09-15-core-fixes.patch`（核心文件差量，不包含全部测试与退出接线变更）。
