# M7 战斗历史

用户选择跳过 M6 菜单栏扩展，直接实现历史。入口为主面板“历史”按钮，打开独立原生窗口，不恢复已移除的侧栏。

## 存储契约

- 使用 macOS 自带 SQLite3，WAL 与事务；数据库在 `~/Library/Application Support/HSRDamageMeter/battles.sqlite`。此阶段直接使用 SQLite C API，隔离在 `BattleHistoryDatabase`；不新增 GRDB 依赖。数据操作由 LiveCombatStore actor 串行执行，不在主线程运行。
- `sessions` 保存 UUID、开始时间、状态、时长、Decimal 文本总量、搜索用角色名及版本化 JSON 快照；`damage_events` 以 session_id + sequence 为唯一键存储原始伤害事件；`app_settings` 保存 schema_version。
- 队伍、角色统计、敌人和分类采用冻结 JSON 快照，避免多个表重复维护同一聚合；未来需要跨场 SQL 分析时再迁移为 Spec 所列的独立 party_members / character_stats 表。记录本身保留 schemaVersion。
- Collector 版本随场次记录。协议未报告游戏版本，保持空值，不用 Nanoka 资料版本冒充。装备关联 loadoutID 预留为空，不代表已经采集配装。
- 每 128 条伤害或约 0.5 秒批量检查点，结算和重置边界立即保存。总量和原始事件在同一事务写入。重复结算幂等；普通列表不载入原始事件。
- 完整结算为 completed；缺失信息结算为 incomplete；重置或被新场次替换为 interrupted。再次启动将上次未结算检查点标为 interrupted。异常退出最多丢失尚未写入的尾部缓冲，不将恢复记录标为完整。
- 磁盘写入失败显示告警并重试；每场原始事件待写缓冲上限8192，异常丢失会标 rawEventsComplete=false；最多暂存32个失败场次，再超限告警。当前实时统计继续运行。

## 使用

历史列表按今天/昨天/更早分组，支持角色名搜索、最新/最早排序及50条分页。详情复用当前伤害图表和类型表，展示结算时敌人快照与最多120区间的累计伤害曲线。JSON 导出包含原始伤害事件与冻结快照，日期使用 ISO 8601，不会覆盖实时面板。

已有旧版内存中的战斗不能追溯恢复；更新后新采集的战斗开始保存。演示数据不自动保存。查看历史时实时统计和浮窗继续接收数据。

## 验证

35项Swift测试通过，2项外部联调跳过。新增：260条Decimal事件与实时累计/DPA一致、原始事件顺序、重复结算幂等、数据库重开、重置与未结算恢复、分页及排序、搜索绑定、累计曲线与历史详情最小窗口离屏渲染。构建、签名和格式检查通过。

## 遗器与光锥

用户确认希望导入遗器及光锥。现有 Socket.IO 的阵容/伤害协议没有实际装备明细；Nanoka 提供图鉴而非账号穿戴词条。后续独立里程碑建议实现配装 JSON 导入，校验角色、槽位、等级、主副词条及光锥叠影，记录来源和导入时间，并与战斗快照关联。本轮不修改 Collector、不索取账号凭据，也尚未实现装备导入器。
