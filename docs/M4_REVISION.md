# M4 面板修订

本次用户要求覆盖 CODEX_SPEC.md 中侧栏、最高单次及按第一名缩放柱长的旧约定。

- 单栏面板；角色、柱形、绝对伤害与百分比使用固定共享边界。保留四名队员，包括零伤害角色。
- 柱长及百分比均为角色累计伤害 / 接收的全队累计伤害。未知归属另列，不猜测召唤者。
- 用户确认召唤物计入所属角色。上游 `src/subscribers/battle.rs` 的 Avatar / Servant / Snapshot 分支发送所属角色 UID；Mac 按该 UID 合并一次。
- 总伤害保留 Decimal 聚合；DPS 仍为伤害 / 本机观察秒数（非游戏内计时）。
- DPA = 全队伤害 / 累计行动值。`OnTurnBegin.action_value` 是上游 `get_elapsed_av` 提供的累计值，不能对事件求和；`OnBattleEnd.action_value` 用于结算。缺失、零行动值或不完整场次显示“—”；行动值回退标记不完整。当前采用用户允许的行动值效率口径，不推算 Cycle。
- 本次没有变更 DLL。新版本运行时字段兼容性仍需实战核验；上游结算行动值本身来自最近一次回合事件。
- 类型翻译以 `src/battle.rs::display_damage_type` 的实际 Socket.IO 标签为准，同时接受内部枚举别名。附加伤害与追加攻击分开；QTE 使用保守的“触发攻击”，不猜测具体技能。未知类型保留原始键以免合并，显示“未知分类”，悬停可看原键。

验证：Swift 22 项中 21 项通过、1 项网络模拟测试跳过（游戏占用 1305）；覆盖累计/重复/零行动值、最终结算、断线、回退、召唤物归属、零伤害队员、未知归属和中文类型。最小 900×620 窗口离屏渲染，不使用 Computer Use。发布构建与签名另行检查。

启动 `dist/HSR Damage Meter.app` 后从完整的新战斗开始观察；仅关闭窗口不会退出旧进程，更新后需通过 Cmd+Q 退出旧 App 再打开新版。原始接收精度及 4.5 上游分类兼容性不因 UI 修改而得到额外保证。

## 并排布局与密度修订

用户后续要求图表同时显示，参考其截图收紧表格，并移除次数。新增 `TeamShareChart`：纵向柱，最高角色固定 180pt 高，其他角色按伤害 / 最高角色伤害缩放；百分比标签仍为角色 / 全队伤害，覆盖上文全队百分比直接决定柱长的旧规则。保留头像、零伤害队员及点击筛选类型明细。

图左表右；伤害表使用 SwiftUI Grid，自然贴合行数，固定角色与数值列宽，支持点击表头排序。类型明细紧凑排列，未选择角色时去掉重复占比列。删除视图切换器、次数列、次数说明；不修改聚合数据或 DLL。最小窗口离屏渲染及 Swift 测试通过（21 通过，1 网络模拟跳过），发布构建及签名检查通过。

## 属性配色与边界对齐

颜色读取既有离线角色资料的 damageType：物理灰、火红、冰蓝、雷紫红、风青绿、量子紫、虚数金；未知角色使用中性灰。已校验遐蝶 1407 = Quantum、长夜月 1413 = Ice。伤害表和类型表使用相同全宽容器与 12pt 内边距；类型表各列伸展，标题与末列分别贴齐左右边界。折叠箭头移至右端，避免系统 DisclosureGroup 缩进影响列边界。
